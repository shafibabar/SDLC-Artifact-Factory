## Narrative

**1. The e2e skill targets an environment that no longer exists.** `E2E/SKILL.md:77-83` says `go-e2e-test` spins up "API + Postgres + Redpanda (+ UI)" as one ephemeral stack with "Testcontainers/docker-compose", and tells frontend tests to use it. `go-e2e-test/SKILL.md:75` now requires an ephemeral `kind` cluster and says "Never docker-compose". Its provisioning script installs three backend charts only (`go-e2e-test/references/environment-provisioning-standard.md:44`): no shell, no remote, no database, broker or ingress. The real-backend tier, which the cross-remote journey depends on (`E2E/references/cross-remote-journey-standard.md:123-129`), therefore has nowhere to run. The script also deletes the cluster on exit (batch B, W3B-1).

**2. The headline journey cannot be relied on, whichever way it goes.** The worked test (`cross-remote-journey-standard.md:73-97`):
- seeds nothing and assumes a row `customer-exports.csv`; the skill has no seeding or teardown standard at all;
- runs in three browser projects against one backend (`:21-25`), so a second run finds the asset already Restricted and the final assertion can pass without the action having had any effect;
- polls `row.isVisible()` through `expect.poll`, while the sibling file says `expect.poll` is for conditions that are not DOM assertions (`flakiness-and-visual-regression-standard.md:36-39`);
- [GK] only re-reads the DOM. If the second remote fetched before the projection caught up and nothing refetches, polling never succeeds;
- [GK] clicks an `option`, which works for a custom listbox only. The component skill and `react-accessibility` use a native `select` (`CT/SKILL.md:53`), which needs `selectOption`.

**3. Setup code the e2e skill promises is missing or inert.** The config (`cross-remote-journey-standard.md:12-27`) has no `retries`, `globalSetup`, `webServer` or `storageState`. [GK] With the default of zero retries, `trace: "on-first-retry"` records nothing. The auth setup (`:138-143`) saves browser storage, but `react-api-client` keeps the access token in memory only (`react-api-client/references/auth-token-standard.md:12`), and [GK] saved storage state does not hold JavaScript memory. No file says how a test-minted token reaches the shell.

**4. The frontend agent relies on e2e content that is not there.** The agent says Playwright covers remote-load failure (`agents/frontend-engineer.md:268`). A search of the e2e skill finds nothing on remote-load failure, `errorElement`, seeding, teardown, smoke tests, or Gherkin. `bdd-feature-file/SKILL.md:150` says the same feature files drive Playwright (batch A, W3A-38). Shell-to-remote contract tests are a required gate (`microfrontend-architecture/references/composition-and-communication.md:67`) and neither testing skill owns them.

**5. Several component-testing claims are false or overstated.**
- [GK] `jest-axe` cannot check colour contrast in jsdom; the rule is off there. `CT/SKILL.md:90`, `react-accessibility/SKILL.md:136` and its contrast reference (`:27`) all say it can.
- [GK] `user.click()` on a disabled button does not throw; it fires nothing. It cannot detect one element covering another in jsdom (`query-priority-and-interaction-standard.md:72`).
- [GK] `onUnhandledRequest: "error"` fails the request, not the test. A component that shows an error state can still pass (`mocking-and-snapshot-standard.md:29`).
- "A handler can't drift" from the contract (`:29`): the handlers shown are untyped literals. They return `{ items, page: 1 }` (`:16`), but the contract convention is cursor pagination with `nextCursor` (`api-contract-design/references/responses-and-errors.md:54`). The e2e fixture has the same error (`cross-remote-journey-standard.md:120`).
- A role query is called direct proof of WCAG 4.1.2 (`CT/SKILL.md:91`). A `div` with `role="button"` and a label passes it and is still unusable by keyboard.

**6. The code the component skill tells an agent to write cannot be written, and would not run if it could.** The TDD hook denied `src/test/setup.ts`, `src/test/handlers.ts` and `src/test/render.tsx` (the declared outputs, `CT/SKILL.md:181-184`), plus `vitest.config.ts`, `playwright.config.ts`, `tests/e2e/global-setup.ts`, `tests/e2e/fixtures/assets.ts`, `main.tsx`, `index.ts` and `.d.ts` files. It also denied `A.tsx` when only `A.a11y.test.tsx` existed, and `D.tsx` when the test sat in `__tests__/` (the layout `react-accessibility/SKILL.md:181` prescribes). No skill gives a Vitest config, `jest-dom` or `jest-axe` matcher registration, a render helper, a per-test `server.use` override for error states, or the `npm run ci` script that agents and CI depend on.

**7. Placement of Playwright in CI is stated three ways.** The agent puts e2e inside `npm run ci` (`agents/frontend-engineer.md:391`). The React workflow comment for that command lists lint, type-check, unit tests, coverage and audit (`ci-pipeline/references/gate-specifications.md:169`). The nightly job runs `make e2e` (`:247`) and e2e on every pull request is an anti-pattern (`ci-pipeline/SKILL.md:194`). The e2e skill says nothing about triggers.

**8. Shared structure gaps.** Neither skill has `sources:`, "Use when" wording, `## Gotchas`, `templates/`, `resources/`, `examples/`, a numbered procedure (component testing has a four-line TDD flow), profile (lean / standard / enterprise) scaling, or an eval suite. Both hard-code the first product. Neither test artifact is in the phase manifest (`implement` is `[]`; batch A, W3A-19).
