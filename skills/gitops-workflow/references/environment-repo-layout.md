# Environment Repository Layout

Self-contained reference for the GitOps environment repository directory structure, with Flux CRD examples for a 3-service, 2-tenant production environment.

---

## Directory Conventions

```
environment-repo/
├── clusters/
│   ├── tenant-alpha-prod/              # Tenant A production cluster
│   │   ├── flux-system/
│   │   │   ├── gotk-components.yaml   # Flux controller manifests (generated by flux bootstrap)
│   │   │   └── gotk-sync.yaml         # Root GitRepository + root Kustomization
│   │   └── namespaces/
│   │       ├── platform/
│   │       │   ├── kustomization.yaml  # Namespace-level Kustomization (App of Apps root)
│   │       │   ├── api-gateway.helmrelease.yaml
│   │       │   ├── data-ingestor.helmrelease.yaml
│   │       │   └── reporting.helmrelease.yaml
│   │       └── monitoring/
│   │           ├── kustomization.yaml
│   │           ├── prometheus.helmrelease.yaml
│   │           └── grafana.helmrelease.yaml
│   └── tenant-beta-prod/               # Tenant B production cluster
│       ├── flux-system/
│       │   ├── gotk-components.yaml
│       │   └── gotk-sync.yaml
│       └── namespaces/
│           ├── platform/
│           │   ├── kustomization.yaml
│           │   ├── api-gateway.helmrelease.yaml
│           │   ├── data-ingestor.helmrelease.yaml
│           │   └── reporting.helmrelease.yaml
│           └── monitoring/
│               ├── kustomization.yaml
│               ├── prometheus.helmrelease.yaml
│               └── grafana.helmrelease.yaml
├── staging/
│   └── shared-staging/
│       ├── flux-system/
│       │   ├── gotk-components.yaml
│       │   └── gotk-sync.yaml
│       └── namespaces/
│           └── platform/
│               ├── kustomization.yaml
│               ├── api-gateway.helmrelease.yaml
│               ├── data-ingestor.helmrelease.yaml
│               └── reporting.helmrelease.yaml
└── dev/
    └── shared-dev/
        ├── flux-system/
        │   └── gotk-sync.yaml
        └── namespaces/
            └── platform/
                ├── kustomization.yaml
                └── api-gateway.helmrelease.yaml  # subset deployed in dev
```

**Rules:**
1. One directory per cluster — never share a cluster directory between tenants.
2. The GitOps agent's source is the cluster-specific path, not a shared path.
3. Adding a new tenant = copying an existing cluster directory and updating values; one PR, no manual cluster operations.
4. Adding a new service = adding one `HelmRelease` file to every cluster's namespace directory; the reconciler picks it up on next poll.

## Flux CRD Examples

### GitRepository — Root Source

```yaml
# clusters/tenant-alpha-prod/flux-system/gotk-sync.yaml (excerpt)
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: environment-repo
  namespace: flux-system
spec:
  interval: 1m           # Poll Git every 1 minute for new commits
  ref:
    branch: main         # Track the main branch
  url: ssh://git@github.com/org/environment-repo
  secretRef:
    name: environment-repo-ssh  # SSH deploy key stored as a Secret
```

**Field annotations:**
- `interval: 1m` — Flux polls Git at this cadence; commits land within ~1 minute of merge. For critical namespaces, reduce to `30s`.
- `ref.branch: main` — always track main; never track feature branches in production.
- `secretRef` — the SSH key that allows Flux to read the private environment repo. Created during bootstrap; stored in `flux-system` namespace.

---

### Kustomization — Namespace-Level Reconciler

```yaml
# clusters/tenant-alpha-prod/namespaces/platform/kustomization.yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: platform-workloads
  namespace: flux-system
spec:
  interval: 5m               # Reconcile every 5 minutes (even if no Git change — drift detection)
  retryInterval: 2m          # On failure, retry after 2 minutes
  timeout: 3m                # Abandon reconciliation attempt after 3 minutes
  prune: true                # Delete resources removed from Git (REQUIRED for drift enforcement)
  sourceRef:
    kind: GitRepository
    name: environment-repo
  path: ./clusters/tenant-alpha-prod/namespaces/platform  # Path within the repo
  force: true                # Overwrite manual edits (enforce drift-as-incident policy)
  healthChecks:              # Wait for resources to become healthy before marking reconciliation done
    - apiVersion: apps/v1
      kind: Deployment
      name: api-gateway
      namespace: platform
```

**Critical fields:**
- `prune: true` — **mandatory**. Without this, removing a file from Git does not delete the resource from the cluster. This is what makes Git the authoritative source of truth for deletions.
- `force: true` — overwrites manual `kubectl edit` changes on next reconcile. This enforces the drift-as-incident policy. Enable in staging and production; can be `false` in dev to allow quick iteration.
- `interval: 5m` — Flux reconciles on a schedule even when there is no new Git commit. This is what detects and repairs drift. The interval is the maximum drift window before self-healing kicks in.
- `healthChecks` — Flux reports the Kustomization as `Ready: False` until listed resources are healthy. This blocks promotion automation from declaring success prematurely.

### HelmRelease — Per-Service Delivery Unit

```yaml
# clusters/tenant-alpha-prod/namespaces/platform/api-gateway.helmrelease.yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: api-gateway
  namespace: platform
spec:
  interval: 10m              # Reconcile the Helm release every 10 minutes
  chart:
    spec:
      chart: api-gateway     # Chart name in the HelmRepository
      version: ">=1.2.0 <2.0.0"   # SemVer range — auto-updates within minor range
      sourceRef:
        kind: HelmRepository
        name: internal-charts
        namespace: flux-system
  values:
    replicaCount: 3
    image:
      repository: ghcr.io/org/api-gateway
      tag: "v1.5.2"          # Pinned image tag — changed by the image update automation or PR
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 500m
        memory: 512Mi
    ingress:
      enabled: true
      host: api.tenant-alpha.example.com
  install:
    remediation:
      retries: 3             # Retry failed install up to 3 times before giving up
  upgrade:
    remediation:
      retries: 3
      remediateLastFailure: true   # Roll back to previous version on upgrade failure
    cleanupOnFail: true            # Remove failed upgrade resources before rollback
  rollback:
    timeout: 10m
    recreate: true                 # Recreate pods during rollback
```

**Field annotations:**
- `chart.spec.version` — use SemVer range for non-breaking auto-updates; pin to exact version for production stability when the chart is under active development.
- `upgrade.remediation.remediateLastFailure: true` — automatically rolls back to the previously successful release on upgrade failure. This implements the "rehearse rollback" principle from Continuous Delivery.
- `values` — tenant-specific values live here, in Git, reviewed by PR. No manual Helm overrides against the live release.

### HelmRepository — Chart Source

```yaml
# clusters/tenant-alpha-prod/flux-system/ (or a shared flux-system kustomization)
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: internal-charts
  namespace: flux-system
spec:
  interval: 5m
  url: https://charts.internal.example.com
  secretRef:
    name: internal-charts-basic-auth  # If the chart registry requires authentication
```

## Tenant Onboarding: Adding a New Tenant

Adding a new tenant's production cluster requires exactly one PR:

1. Copy an existing cluster directory:
   ```bash
   cp -r clusters/tenant-alpha-prod clusters/tenant-gamma-prod
   ```
2. Update `gotk-sync.yaml` to point at the new cluster's API server (if using Argo CD) or update the SSH key secret reference.
3. Update all `HelmRelease` value blocks: `host: api.tenant-gamma.example.com`, tenant-specific resource quotas.
4. Update `gotk-sync.yaml`'s cluster name and any cluster-specific labels.
5. Merge the PR. On next poll, Flux on the new cluster picks up its directory and stamps the environment.

The new cluster must have Flux bootstrap applied first (`flux bootstrap github --path=clusters/tenant-gamma-prod`), which creates the `flux-system` namespace and installs the controllers. The controllers then self-configure from the committed `gotk-sync.yaml`.

## Removing a Service From an Environment

1. Delete the service's `HelmRelease` file from the namespace directory.
2. Merge the PR.
3. Because `prune: true` is set on the parent `Kustomization`, Flux deletes the `HelmRelease` resource from the cluster on next reconcile.
4. The Helm controller then uninstalls the chart.

This is a fully reversible Git operation — reverting the PR re-adds the service.
