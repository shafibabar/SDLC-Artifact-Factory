# D020: skills/ddd-agent-handoff replaces the originally proposed 'ddd-orchestrator' concept (a 14-role sub-agent network with its own references/assets/guidelines subtree and an embedded pytest test suite). Built instead as a single flat cross-cutting skill (phase: cross-cutting, owner: factory-governance, matching glossary-management/methodology-review) containing only an Agent Boundary Matrix (pointing to the 11 real agents and their existing skills) and a short Handoff Protocol. No new agents were created.

**Date:** 2026-07-22

**Rationale:** The 14 draft roles mapped onto this repo's existing 13 agents with zero true gaps once corrected — several draft rows were mislabeled (e.g. Context Map work belongs to domain-modeler, not enterprise-architect) or collapsed onto the same agent (DevOps+Platform -> platform-engineer; Security+Compliance -> security-architect/security-engineer). Separately, ~7 of the proposed reference files (ddd_glossary, ubiquitous_language, context_mapping_patterns, cqrs_event_sourcing, saga_patterns, event_storming_template, adr_template) duplicated content already owned by existing skills (aggregate-design, ubiquitous-language, context-map-patterns/bounded-context-mapping, cqrs-pattern, event-driven-patterns, event-storming-facilitation, adr-authoring) — recreating them would have created a second, competing source of truth for DDD terminology in a repo with a terminology-drift-detector hook. The draft's procedural 'Triage Algorithm' was also dropped as reasoning/decision-making that belongs in an Agent, not a Skill, per this repo's Component Architecture rule; the Agent Boundary Matrix (a selection-criteria table) was kept since CLAUDE.md explicitly allows that as Skill knowledge. Full analysis recorded on GitHub issue #48.

**Alternatives rejected:**
- Scaffold the meta-prompt literally (skill.md, pytest test suite, 14 fresh roles) — rejected: wrong filename/frontmatter shape for this repo's verified auto-discovery, and a test convention (embedded pytest) that contradicts CLAUDE.md's 'skills have no build step or test suite' rule
- Keep the 14 conceptual roles as a separate taxonomy layered on top of the 13 agents — rejected: an unnecessary second vocabulary for the same 13 agents, adding indirection with no benefit
- Build the full references/assets/guidelines package anyway alongside the 7 pre-existing overlapping skills — rejected: creates duplicate/competing DDD terminology
