# D029: Establish research/domain-driven-design/ as a new research cluster (Evans' Domain-Driven Design, Vernon's Implementing Domain-Driven Design / Effective Aggregate Design, Khononov's Learning Domain-Driven Design), researched as a prerequisite phase before extensively rebuilding skills/aggregate-design/SKILL.md, rather than writing the rebuild from general LLM knowledge of these widely-known books. Corrected aggregate-design's prior header framing ('these rules are non-negotiable') to match Vernon's own explicitly-not-absolutist stance, with a documented, criteria-gated exception process replacing false absolutism.

**Date:** 2026-07-24

**Rationale:** Shafi asked for an extensive rebuild of aggregate-design including 'every possible information, practice, decision, nuance' from the DDD Aggregate literature, split across multiple references/ files with explicit decision-tree structure. Checking research/ first (per this repo's own established discipline) found no dedicated research existed for the actual foundational DDD Aggregate texts, despite aggregate-design's existing five rules clearly summarizing them -- writing exhaustive content without first researching the primary sources would be exactly the 'memory-sourced content' anti-pattern requirements-analysis already names as a defect. Vernon's research (research/domain-driven-design/implementing-ddd-vernon.md) surfaced the non-negotiable-vs-Vernon's-real-position gap as the single most consequential finding of the whole rebuild -- a repo-authored skill had drifted to a stricter position than its own primary source actually holds.

**Alternatives rejected:**
- Write the rebuild directly from general knowledge of Evans/Vernon/Khononov without a dedicated research pass, given how widely known these books are -- rejected: this is precisely the 'memory-sourced' risk this repo's own requirements-analysis skill names as a defect, and the non-negotiable-vs-Vernon's-real-position finding would likely have been missed without the dedicated, grounded research pass that specifically re-examined the existing skill's claims against the source
- Keep the DDD research folded into the existing software-architecture cluster rather than a new dedicated cluster -- rejected: DDD tactical/strategic design is a distinct discipline from general software architecture, and a dedicated cluster keeps the three foundational DDD texts discoverable together for whichever skill needs them next (bounded-context-mapping, subdomain-distillation, domain-event-catalog all cite DDD literature and could benefit from the same cluster later)
- Merge Khononov's Business Logic Design Pattern gate and Event Sourcing content into the originally-planned reference file structure rather than absorbing them into existing files (d7's go-implementation-patterns.md, d8's decision-trees-and-worksheets.md) -- rejected as unnecessary: both additions fit naturally into already-planned files without requiring new sub-issues or GitHub issue renumbering after issues were already created
