# D043: Write-time checks also run on Edit, and changing an approved artifact sends it back to draft — its phase stays approved but no later phase can be completed until it is re-approved (#1288)

**Date:** 2026-10-18

**Rationale:** Every artifact/code check in hooks.json matched `Write` only, so an Edit — revisions in approval loops, most of the TDD cycle — skipped frontmatter validation, the TDD gate, manifest registration and memory indexing, terminology drift and methodology review. The checks now match `Write|Edit`: the frontmatter check validates the post-edit text (applying old_string/new_string to the file as the Edit tool would), the TDD gate treats an edit as a change, the PostToolUse checks read the edited file from disk, and the methodology hook has a second agent handler (`if: Edit(**/artifacts/**)`) that Reads the whole file (inside the project, so permitted). The naming check stays Write-only (an Edit cannot create a file). Shafi chose (a): an edit to an approved artifact resets it to draft (`reopened_on`, cleared by `approve`); a rewrite with identical text (tool_response.originalFile unchanged) does not. For the phase, he chose "flag, block next gate": the earlier phase stays approved so in-flight work is not halted, `status` lists `needs_reapproval`, and `complete` of that phase or any later one refuses until the artifact is re-approved.

**Alternatives rejected:**
- Keep approval on edit and log it in history only — rejected by Shafi: lets phase gates pass on content nobody approved.
- Reopen the whole earlier phase — rejected by Shafi: blocks the next phase's agents mid-work over a one-line fix.
- Flag only, enforce nothing — rejected by Shafi: visible but unenforced.
