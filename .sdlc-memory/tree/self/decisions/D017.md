# D017: schemas/sdlc-config.schema.json and schemas/sdlc-manifest.schema.json (Draft 2020-12) formalize skills/sdlc-config-management and skills/artifact-manifest's already-documented Output Format shapes exactly, rather than inventing a new shape. sdlc-manifest.schema.json validates only the per-product manifest INSTANCE, not the master artifact-type catalog (which stays a prose table, extended over time — type is a free-form pattern, not a closed enum, to avoid needing a schema update on every new artifact-producing skill).

**Date:** 2026-07-20

**Rationale:** Both governance skills already had complete, worked JSON examples in their Output Format sections from when they were written (Chunk 18) — the schema's job was to encode what was already specified, not design something new. Tested against the real jsonschema library (Draft202012Validator): both skills' exact worked examples validate cleanly, and a battery of deliberately invalid instances (missing required fields, bad enums, malformed dates/semver/slugs, unknown fields, empty traceability refs) are all correctly rejected — 15 negative cases total across both schemas.

**Alternatives rejected:**
- Also schema-ize the type catalog as a closed enum — rejected per the skill's own statement that the catalog is a representative cross-section extended over time; a closed enum would need updating on every new artifact-producing skill
