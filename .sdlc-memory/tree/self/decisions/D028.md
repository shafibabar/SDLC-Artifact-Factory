# D028: Adopt a formalized scripts/ and assets/ subdirectory convention for individual skills (skills/<name>/scripts/*.sh, skills/<name>/assets/*), alongside the existing references/ progressive-disclosure tier -- codified in a new cross-cutting skill, skill-authoring-standards, and a short new CLAUDE.md section. A skill-owned script is invoked by the agent applying that skill (via the Bash tool, at a path the skill's own body names), distinct from the pre-existing repo-root scripts/ convention (hook- or command-invoked) -- same Scripts = Actions rule, different invocation context. adr-authoring (rebuilt v3.0.0) is the first real skill to use this shape: assets/adr-template.md (copyable) plus scripts/scaffold-adr.sh and scripts/validate-adr.sh (deterministic generation/validation), each with its own tests/scripts/*.test.sh.

**Date:** 2026-07-23

**Rationale:** research/ai-agent-engineering/mastering-claude-code-agent-skills-gale.md established the three-tier progressive disclosure rubric (metadata/body/references) already correctly practiced by several skills, but found no repo precedent for scripts/assets since this repo had never used them -- Shafi explicitly asked for skills to move beyond prose-only templates into scripts that actually generate and validate artifacts (documents, code, test suites, reviews), matching the real Claude Agent Skills format's scripts/+assets/ convention rather than this repo's own invented shape. Scoped to skill-authoring-standards (not a new component type in CLAUDE.md's closed Component Architecture table) because scripts/assets are sub-parts of the existing Skill component, not a new top-level component -- the existing Scripts = Actions rule already governs the behavior, only the location and caller differ.

**Alternatives rejected:**
- Leave scripts/assets undocumented and let each skill invent its own ad hoc convention as the need arises -- rejected: exactly the 'imitate whichever skill was refactored most recently' problem skill-authoring-standards exists to end, and the whole point of doing this now is to establish one citable convention before more skills adopt it inconsistently
- Treat skill-owned scripts as a new top-level component type distinct from the existing repo-root Scripts -- rejected: the underlying rule (atomic, deterministic, stateless, single-purpose) is identical; only the invocation context differs, which does not warrant a new row in CLAUDE.md's Component Architecture table
- Retrofit scripts/assets onto the other ~140 existing skills as part of this same chunk -- rejected: applying the new standard happens going forward, per refactor session, not as a retrofit-everything chunk, matching this repo's established forward-apply pattern for other skill-shape changes
