# D041: The methodology-review hook loads its criteria through the Skill tool and fails closed; the acceptance-test agent hook is removed from the shipped hooks.json (#1255)

**Date:** 2026-10-18

**Rationale:** Debug logs (Claude Code 2.1.302) showed both `type: "agent"` PostToolUse hooks do run, but the methodology hook's subagent was told to Read `skills/methodology-review/SKILL.md`. In an installed user's product repo that file is outside the project; hook subagents run without the ability to ask for permission, so the Read was denied and the subagent returned `ok: true` without its criteria — every artifact passed unreviewed. Hook prompts do not expand `${CLAUDE_PLUGIN_ROOT}`. A throwaway-plugin probe proved a hook subagent can load a plugin skill with the Skill tool (and run simple Bash). The hook now loads `sdlc-artifact-factory:methodology-review` via the Skill tool, reviews `tool_input.content`, returns `{ok, reason}`, fails closed when it cannot load its criteria, and is narrowed with `if: "Write(**/artifacts/**)"`. Shafi chose to remove the acceptance-test hook: it spawned a subagent on every Write/Edit for every user but only applied to this plugin's own components, and its tests take longer than its 300 s timeout.

**Alternatives rejected:**
- Command-type methodology hook — rejected again for the D014 reason: methodology judgment is not reducible to deterministic checks.
- Embed the review criteria in the hook prompt — rejected: duplicates `methodology-review`, the single source of the criteria.
- Absolute or `${CLAUDE_PLUGIN_ROOT}` path in the prompt — rejected: the variable is not expanded in hook prompts, and Read outside the project is denied anyway.
- Keep the acceptance-test hook narrowed with `if`, or move it to repo-only settings — rejected by Shafi: it still could not finish within its timeout; `tests/run-smoke-tests.sh --changed` covers the need.
