# D047: Fresh-Eyes Wave 2 design decisions — CloudEvents with new event types for breaking changes, one read-side ladder decided before read models, service decomposition in container-diagram, no multi-tenancy default, agent-run workshops (#1376)

**Date:** 2026-11-02

**Rationale:** The Wave 2 audit (`discovery/fresh-eyes/wave-2-findings.md`, #1377, 50 findings) found the domain-modeling and architecture skills teaching the same concepts with different answers, skills with no owning agent, and first-product defaults applied to every product. The product owner accepted all 14 recommendations:
1. **Event envelope and versioning:** CloudEvents 1.0 with extensions (`correlationid`, `causationid`, `tenantid`); a breaking change is a **new event type**, never a `.vN` suffix. `event-schema-design` owns the rule; `domain-event-catalog` points to it.
2. **`event-schema-design` ownership:** data-architect owns serialization and the schema registry; the domain-modeler keeps payload meaning in `domain-event-catalog`.
3. **Orchestration:** `workflow-orchestration` owns orchestration, using Richardson's rule for when to orchestrate; `event-driven-patterns` keeps choreography and points to it.
4. **Read side:** one ladder in `cqrs-pattern` (API composition across services; a simple read model inside a service; projections only on a named trigger). Owner enterprise-architect, phase design, decided **before** `read-model-design` runs.
5. **Context-map skills:** split by responsibility, not merged — the patterns in `context-map-patterns`; discovering and drawing the map in `bounded-context-mapping`.
6. **Service decomposition:** moves to `container-diagram`. Lean defaults to a modular monolith; standard and enterprise use granularity checklists. CLAUDE.md defaults change to match.
7. **Multi-tenancy:** no plugin-wide default. The isolation model is chosen from each product's NFR and compliance input; physical isolation (the stamp model) becomes an example, and SOC 2 is not claimed to require it. Tenancy is decided before the deployment view.
8. **Workshops:** Event Storming and Domain Storytelling get an agent-run mode built from named artifacts, with assumptions labelled and open questions sent to the product owner; a real human session stays optional.
9. **Vocabulary:** a product's per-bounded-context Ubiquitous Language lives in the product's own artifacts; `glossary-management` stays the plugin's vocabulary; the terminology drift hook reads both.
10. **Code in design skills:** Go code moves out of Design-phase skills into the `go-*` skills; design skills are stack-neutral.
11. **Unowned skills:** `message-broker-selection`, `workflow-orchestration` and `grpc-contract-design` join enterprise-architect; gateway placement is decided at Design via `container-diagram`, gateway configuration by platform-engineer at Deploy (`api-gateway-design`).
12. **Gateway and zero trust:** every service still verifies identity; the gateway is only the first check.
13. **C4:** the deployment view is a section of `container-diagram`; component diagrams only for services that differ from the default (manifest change); plain-text (ASCII) diagrams are the primary notation, Mermaid optional.
14. **Subdomain classification:** a pipeline step after Event Storming Big Picture, with a registered `subdomain-classification` artifact (lean: a short table).

Also from the findings: attributions to Kaiser, Lilienthal & Schwentner and *Team Topologies*, which have no research file, are dropped; "Hohpe" citations are re-sourced to Richardson and Roy.

**Alternatives rejected:**
- A house event envelope, or `.vN` version suffixes — two rules already drift; CloudEvents is the standard the integration layer expects.
- Merging the two context-map skills — they hold different jobs; merging loses the separation.
- A single plugin-wide tenancy default (physical isolation) — it came from the first product and overbuilds every other.
- Requiring a human workshop for every product — the agent runs Design alone; the requirement would be violated on every run.
