# D018: Skill/agent smoke tests split into a Contract tier (a fast, cheap LLM-answered question about one documented fact — what the 6 broken *.fixture.sh files became once fixed) and a new Acceptance tier (a live agent dispatch that must actually invoke the named skill and produce the real work product — a written artifact or real code — validated structurally and, where a toolchain exists, mechanically). Contract stays the fast canary; Acceptance proves the agent can do its job, not just recite facts about it. Selection for --skill/--agent/--changed and the new automatic hook derives from agents' existing frontmatter skills: list (grepped for ownership) rather than a second, hand-maintained tag system.

**Date:** 2026-07-21

**Rationale:** The prior six skills/agents test files were pure two-variable shell fixtures that never sourced tests/lib/harness.sh — run-smoke-tests.sh's glob picked them up and silently reported 0 passed/0 failed, not a failure. Separately, even a fixed Q&A test ("what's the word limit?") never proves an agent can invoke a skill and produce its real output — Shafi's explicit objection. Reusing the skills: frontmatter block (already the single source of truth for which agent owns which skill) for selection avoids a second manifest that would drift from it; git diff --name-only drives change-based selection, the same idea as jest --onlyChanged / nx affected.

**Alternatives rejected:**
- A hand-maintained tag/manifest file mapping skills to owning agents and to test tiers — rejected: agents/*.md's skills: list already is that mapping; a second copy would just drift out of sync with it.
