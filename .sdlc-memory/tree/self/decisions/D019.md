# D019: Every live agent dispatch in tests/lib/harness.sh's smoke_test_acceptance (and tests/hooks/hooks-wiring.test.sh, fixed alongside) uses --permission-mode auto, not bypassPermissions or acceptEdits.

**Date:** 2026-07-21

**Rationale:** Found by live testing: --permission-mode bypassPermissions maps to --dangerously-skip-permissions, which Claude Code refuses to honor when the process runs as root (this environment does) — this was silently causing hooks-wiring.test.sh's second case to fail (the dispatch errored before attempting the write, so the file predictably never landed, and the test's first case — file absent after a blocked write — happened to read as a pass for the wrong reason). --permission-mode acceptEdits auto-accepts Write/Edit but still blocks Bash approval; several agents in this plugin declare tools: [Bash] only (backend-engineer, frontend-engineer — no Write tool at all, so they create files via Bash heredocs), and under acceptEdits those agents hang or error indefinitely waiting for a Bash approval that never arrives in a headless -p session. auto grants both non-interactively and was confirmed to still enforce this repo's PreToolUse/PostToolUse hooks correctly.

**Alternatives rejected:**
- bypassPermissions/--dangerously-skip-permissions — rejected: refused outright when running as root, which this environment does
- acceptEdits — rejected: leaves Bash-only agents unable to create files non-interactively
