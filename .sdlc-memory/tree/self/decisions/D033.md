# D033: Adopt six canonical labels (discovery, agent, skill, bug, documentation, enhancement -- multiple allowed per item) as mandatory on every issue, sub-issue, and PR in the SKILL GEN Project. Retroactively labeled all 249 existing issues/PRs by title-pattern classification, spot-checked and verified 249/249 correct. Enforced going forward by requiring --labels on plan_start.py and save_draft.py add (validated before any GitHub mutation runs), with exec_start.py mirroring a sub-issue's labels onto its PR rather than asking for a separate choice. Commits are explicitly out of scope -- GitHub has no commit-label mechanism, and Shafi confirmed conventional-commit prefixes are not wanted either.

**Date:** 2026-07-24

**Rationale:** Shafi asked for consistent, retroactive-and-future labeling across the project's issues/sub-issues/PRs/commits. Applying the fix uncovered a second GraphQL 'Projects (classic)' deprecation bug beyond the one skill-refactor.md already warns about for gh issue edit body edits: gh pr edit --add-label fails outright on this repo (exit 1, label never applied) via the same deprecated-field GraphQL path, while gh issue edit --add-label works. Standardized both the retroactive script and the new project.py/gh.py tooling on the REST labels endpoint (gh api repos/<owner>/<repo>/issues/<n>/labels, which treats PRs as issues) instead, since it is confirmed reliable for both and removes the split-path inconsistency entirely.

**Alternatives rejected:**
- Use gh pr edit --add-label for PR labeling as originally implemented -- rejected after empirical failure: it returns exit 1 and never applies the label on this repo, the same category of GraphQL Projects-classic bug skill-refactor.md already documents for gh issue edit body edits
- Let exec_start.py pass --label flags directly on gh pr create -- rejected as an unverified assumption riding on the same buggy code path; replaced with applying labels via the proven-reliable REST endpoint immediately after PR creation, using the sub-issue's already-set labels as the single source of truth
- Treat commits as in-scope via conventional-commit-style prefixes (feat:/fix:/etc.) -- rejected per Shafi's explicit answer: commits are skipped entirely rather than inventing a parallel, unrequested convention
