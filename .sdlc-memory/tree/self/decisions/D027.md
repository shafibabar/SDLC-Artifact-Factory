# D027: Introduce Architecture Principle as a new, distinct output artifact type (a per-product PRINCIPLES.md catalog, owned by enterprise-architect via adr-authoring) alongside the existing ADR artifact type -- durable, cross-cutting guidance that many future ADRs cite, as opposed to a single point-in-time decision. Scoped narrowly: taught inside adr-authoring's own references/architecture-principles.md (format template, generalization test, storage convention, one illustrative worked example), not spun off into a separate skill file.

**Date:** 2026-07-23

**Rationale:** Fundamentals of Software Architecture Ch. 18 (research/software-architecture/fundamentals-of-software-architecture-richards-ford.md) was the only research source that named adr-authoring as a primary refactor target, and its one genuine gap was exactly this missing distinction -- several ADR-worthy items already in this repo (e.g., integration-design's 'asynchronous is the default' prose rule) are really principles, not decisions, and adr-authoring had no separate authoring path for them, risking durable guidance getting buried and silently lost inside a single ADR's Rationale if that ADR is ever superseded. Kept inside adr-authoring rather than a new skill because the artifact is small (one companion format + template) and no other skill or agent currently needs to reference Principle-authoring mechanics independently of ADR-authoring -- the MVP-dependency-pull threshold from D021 (pull in a new skill only when a real dependent need exists) was not met.

**Alternatives rejected:**
- Spin off a separate architecture-principle-authoring skill -- rejected: no dependent skill/agent needs Principle mechanics independently of adr-authoring today; would add a discovery/maintenance surface for a companion concept this small
- Retroactively formalize this repo's own existing conventions (CLAUDE.md's tables, integration-design's prose rule) as named Principle records now -- rejected as out of scope for a single-skill content refactor; recorded as open question Q003 for Shafi to decide separately
- Leave the decision-vs-principle distinction as prose-only guidance inside adr-authoring's Rationale section with no dedicated artifact type -- rejected: the book's own gap analysis is specifically that this needs a distinct, citable artifact, not just advice to write better ADRs
