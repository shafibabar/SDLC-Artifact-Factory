# D042: Every agent declares the same tools — Read, Write, Edit, Glob, Grep, Bash — enforced by the agent schema, and preloads memory-recall as a third mandatory cross-cutting skill (#1254)

**Date:** 2026-10-18

**Rationale:** Claude Code's agent `tools:` field is an allow-list. CLAUDE.md's rule "agents that run shell commands declare `tools: [Bash]`" treated it as additive. A live probe showed backend-engineer received Bash alone (its files bypassed every Write hook), product-strategist Read and Write (no Bash for memory-recall or validators), and ux-architect (`tools: []`) nothing. Bash is needed by every agent for memory search and validators, so per-agent lists would converge anyway; Shafi chose one explicit standard set over inheriting every tool (which would bring in web and user MCP tools unpredictably). No agent preloaded `memory-recall`, and installed users never receive CLAUDE.md, so the memory rule never reached agents; it is now mandatory in every agent's `skills:` (`lint-relationships`). Glob and Grep stay declared for builds that have them; this build (2.1.302) folds search into Bash, and unresolved entries are ignored.

**Alternatives rejected:**
- Omit `tools:` and inherit everything — rejected by Shafi: pulls in web access and whatever MCP servers a user has, so agent behaviour varies by machine.
- Tailored per-agent lists — rejected: every agent needs Bash for memory-recall and validators, so the lists would be nearly identical and drift-prone.
- Give recall a non-Bash path (orientation hook injects context) — rejected: agents still need Bash for skill validators, and the abstract-level orientation already exists; drill-down needs the retrieve script.
